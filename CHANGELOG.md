## [1.1.0] - 2026-11-06

### Trust, Reproducibility, and Shared-Memory Foundation

This release responds to the deep-research audit of v1.0.0. It prioritizes
correctness guarantees over new surface area, and documents explicitly what is
implemented, experimental, or still planned (`docs/IMPLEMENTATION_STATUS.md`).

#### Fixed (critical)

* **Stale context leak (P0).** `get_relevant_context` now detects workspace
  changes *before* any cache lookup; cache entries are keyed by snapshot id plus
  parser/retrieval/embedder versions. Unsynchronized changes invalidate the cache
  and mark the package `STALE` with `contextContract.mustSyncBeforeEdit = true`.
* **Destructive build (new finding).** `scripts/build.js` no longer writes proxy
  `package.json`/`index.js` files through npm workspace symlinks. The old script
  silently overwrote each package manifest and corrupted clean installs.
* **Updater ignored downloaded artifacts (P0).** Plugin updates now extract the
  verified archive into staging, validate a per-file SHA-256 manifest, install it
  atomically under `.projectmind/plugins/<id>/versions/<version>`, apply its
  instruction/skill assets, and roll back on verification failure.
* **Optional checksum (P0).** Missing SHA-256/signature is now a hard failure;
  checksums are compared in constant time. Unsigned updates are refused.
* **Fake core update (P0).** `projectmind update` previously reported success
  without changing anything. It now stages a verified artifact and applies it to
  non-git installs; git checkouts are refused in favour of `git pull`.
* **Transparent HTTP.** Update downloads require HTTPS and an allowlisted host,
  reject redirect downgrades, and enforce redirect/size limits.
* **Empty LICENSE.** Added the MIT license text matching `package.json`.
* **Missing lockfile.** Committed `package-lock.json`; CI uses `npm ci` and a
  clean-room rebuild of the packaged source archive.

#### Added

* Schema v4: `memory_events` (append-only, hash-chained), `workspace_snapshots`,
  `index_manifest`, `memory_conflicts`, `code_symbols`, `code_graph_edges`,
  `file_chunks`; bi-temporal columns on knowledge and decisions.
* AST indexing for TypeScript/JavaScript via `@babel/parser`: symbols, imports,
  re-exports, routes, SQL/Prisma models, and resolved dependency edges
  (relative, workspace packages, and `tsconfig` `paths`).
* Full-file streamed SHA-256 plus bounded chunk hashes; large files are fully
  hashed and marked `truncated` for analysis rather than silently trusted.
* Namespaces and actor identities (`project/shared`, `project/agent/<id>`,
  `project/user/<id>`, `project/branch/<name>`, `project/task/<id>`).
* Optimistic concurrency with conflict proposals and merge/reject resolution.
* `asOf` historical retrieval and supersession-aware current retrieval.
* Hybrid retrieval with per-hit score breakdown, matched terms, `why`, and
  path/line evidence; code-graph neighbour expansion; persisted embeddings with
  model/version/hash metadata.
* MCP tools: `get_health`, `get_memory_events`, `record_memory_event`,
  `get_memory_conflicts`, `resolve_memory_conflict` (27 tools total).
* CLI: `health`, `manifest`, `memory events`, `memory conflicts`.
* `npm run benchmark` (Recall@1/3/5, MRR, explainability coverage, latency,
  stale-hit checks) and `npm run release:package` (core archive, 9 plugin
  bundles, `index.json`, `SHA256SUMS`, `release-manifest.json`, self-verification).
* Clean-room CI job that extracts the release archive, runs `npm ci`, builds,
  tests, and benchmarks the extracted copy.

#### Changed

* Built-in vector backend is now named `hash-feature-v2` and described as
  lexical feature-hash reranking — not a learned semantic embedding.
* `planned` knowledge no longer becomes `verified` merely because a file exists
  in the same module; it requires route/schema/test/explicit-source evidence.
* Test count is 89 checks (up from 62) and is generated by the runner rather than
  hardcoded in documentation.

#### Security

* Tar extraction rejects absolute paths, `..`, symlinks/hardlinks, devices,
  oversized archives, and too many entries.
* Plugin bundles must declare every file with its SHA-256; undeclared files are
  rejected.
* Event log is append-only at the database level (triggers), with a verified hash
  chain surfaced by `projectmind health`.

#### Known limitations

* Learned local embeddings, tree-sitter parsers for non-TS languages, encryption
  at rest, retention/compaction, and Sigstore-style artifact signatures remain
  planned. See `docs/IMPLEMENTATION_STATUS.md`.

## [1.0.0] - 2026-11-06

### Initial Production Release

#### Core Intelligence & Persistent Memory
* **3-Layer Memory Architecture**:
  * Layer 1 (Core Memory): Permanent project identity, tech stack, constraints, and schema version.
  * Layer 2 (Project Knowledge): Searchable SQLite + FTS5 (BM25) and local vector reranking for modules, symbols, routes, models, and ADRs.
  * Layer 3 (Task Context): Ephemeral, token-budgeted retrieval state isolated from permanent knowledge.
* **7-Stage Controlled Bootstrap**: Analyzes project metadata, entrypoints, module topology, symbols, HTTP routes, database models, and SHA-256 fingerprints without modifying source files.
* **Provenance & Verification Status**: Tracks `verified`, `inferred`, `planned`, `unverified`, and `outdated` records with confidence scores.
* **Smart Auto Mode Engine**: Autonomous zero-command workflow initializing project memory on first encounter and synchronizing delta edits after tool usage.

#### Universal MCP Server
* Implemented JSON-RPC 2.0 MCP server with `stdio` transport.
* Exposed 22 intelligence tools across discovery, context retrieval, impact analysis, architectural decision recording, and token efficiency.

#### Agent Integrations (9 Platforms)
* **Google Antigravity**: Native plugin (`.agents/plugins/projectmind`), MCP config, autonomous skill, and lifecycle hooks (`SessionStart`, `PreInvocation`, `PostToolUse`, `Stop`).
* **Anthropic Claude Code**: Native plugin, MCP config, skill, and lifecycle hooks (`SessionStart`, `UserPromptSubmit`, `PostToolUse`, `Stop`).
* **OpenAI Codex**: MCP `initialize` server instructions, skill bundle, and `AGENTS.md` integration.
* **Cursor**: Native v1 lifecycle hooks (`workspaceOpen`, `sessionStart`, `beforeSubmitPrompt`, `afterFileEdit`, `stop`), `.cursor/rules/projectmind.mdc`, and MCP config.
* **Google Gemini CLI**: Strict JSON stdout lifecycle hooks, skill, `GEMINI.md`, and MCP config.
* **GitHub Copilot**: Custom instructions (`.github/copilot-instructions.md`), prompt files, and VS Code MCP integration.
* **OpenCode**: Dynamic MCP client, `AGENTS.md` instructions, skill bundle, and portable hooks.
* **Hermes Agent**: Native MCP client, `HERMES.md` guidelines, and memory loop integration.
* **DeepSeek Harness (`dsh`)**: Profile plugin, `DEEPSEEK.md`, skill bundle, and hook runner.

#### Plugin SDK & Distribution System
* Created `@projectmind/plugin-sdk` with `RuntimeResolver`, `PortableHookRunner`, `ConfigWriter`, `ManifestValidator`, and `PluginRegistry`.
* Implemented comprehensive Update & Upgrade Manager (`UpdateManager`, `UpdateLock`, `UnifiedUpdateManifest`) directly integrated with GitHub Releases (`Rootx202/ProjectMind`).
* Added CLI commands: `projectmind update check`, `projectmind update`, `projectmind upgrade check`, `projectmind upgrade`, `projectmind plugin outdated`, and `projectmind plugin update <agent|--all>`.
* Cryptographic SHA-256 verification and automatic atomic rollback on failure.
* Mutex lockfile mechanism (`.projectmind/.update.lock`) preventing concurrent updates.
* Developed unified CLI (`projectmind plugin list`, `search`, `install`, `verify`, `update`, `disable`, `enable`, `uninstall`, `doctor`).
* Non-destructive uninstall guarantee: agent configurations can be removed without touching or deleting `.projectmind` SQLite databases.
* Automated packaging tool (`scripts/package-plugins.js`) producing `.tar.gz` bundles with `SHA256SUMS` and `index.json`.
* Cross-platform installers: POSIX `install.sh` for Linux/macOS and PowerShell `install.ps1` for Windows.

#### Security & Privacy
* Local-first indexing/retrieval with no telemetry. (The updater introduced in this release does make explicit GitHub Release requests; see 1.1.0.)
* Secret exclusion engine: automatically ignores `.env`, private keys, certificates, and redacts credentials before indexing.
* Path traversal defense: validates canonical paths inside workspace boundary.
* Prompt injection protection: sanitizes untrusted comments and files before context inclusion.
